Igniting VLMs toward the Embodied Space 训练细节解析

这份整理只聚焦“模型怎么训练”的部分，核心对象是论文提出的 WALL-OSS。内容分成四层：论文明确公开的训练课程、损失与数据；官方开源实现能补充的默认配置；论文与实现之间的对应关系；以及论文没有完全公开的关键训练细节。

核心模型：WALL-OSS 主题：从 VLM 到具身 VLA 的 staged curriculum 整理时间：2026-04-17
At A Glance

一句话抓住训练核心

WALL-OSS 的训练主线可以概括成一句话：先把 VLM 变得“懂具身空间、懂粗粒度动作”，再把它切换到高频连续控制。论文把这个过程分成 Inspiration Stage 和 Integration Stage 两大阶段，并在其上再叠加 Unified Cross-Level CoT，把“指令 → 推理 → 子任务 → 连续动作”统一进一个可微的单模型路径。

Architecture

1. 模型结构与训练对象

1.1 紧耦合 MoE，而不是松耦合 side head

  • 论文明确强调，WALL-OSS 不是简单“给 VLM 外接一个动作头”，而是一个 tightly coupled MoE architecture。
  • 其核心思想是在 VLM 主干内部为动作相关信息开专门通路，同时保留视觉语言通路，避免纯 side-branch 设计造成语义和动作绑定过弱。
  • Static router 会把 action-centric features 路由到 Action FFN，把视觉语言特征路由到 Vision-Language FFN。

1.2 为什么是静态路由

  • 论文明确写了：这里不是 learned softmax/top-k router，而是 static routing。
  • 这样做的目的，是让不同模态在不同训练阶段的更新更可控，避免动态门控把训练不稳定性带到动作学习里。
  • 官方开源实现也印证了这一点：TokenTypeRouter 直接按 token type 做专家分派，配置里默认 num_experts = 2，并启用 mlp_moe。
训练上的关键含义：WALL-OSS 的主旨不是“保护 VLM 不被动作破坏”，也不是“让动作头自己学”，而是通过一条受控的 MoE 路由，把语言、视觉、动作绑定在一起，同时保留可训练性。
Stage 1

2. Inspiration Stage：先把 VLM 点燃到具身空间

这一阶段的目标不是直接做高频控制，而是先让 VLM 学会“看懂具身场景、理解空间关系、知道粗粒度动作在说什么”。论文明确说这一步会重用预训练 VLM 的原始 FFN，同时加入 embodied VQA 和离散动作目标。

2.1 这一阶段学什么

  • embodied VQA：增强空间推理、进度理解、任务阶段判断。
  • instruction following：维持或增强指令遵循能力。
  • temporal order / causality modeling：补足具身环境里的时序与因果理解。
  • 离散动作建模：把连续动作变成 FAST token，让 VLM 用 next-token 风格先学粗动作先验。
  • 论文文字还提到了 masked language modeling 和 image/video-text contrastive learning，说明这一阶段不是单纯 SFT，而是一个多任务具身预热阶段。

2.2 FAST 离散动作具体怎么接入

  • 论文在公式里直接写成 z(1:K) = FAST(a)。
  • FAST 的处理路径写得很清楚：DCT → Quant → BPE。
  • 作者的目的，是把连续动作先变成 VLM 熟悉的离散 token，从而借用 next-token 学习范式建立语言和动作的粗绑定。

2.3 论文明确给出的 Inspiration loss

  • VQA / 文本部分是标准自回归 token likelihood。
  • 离散动作部分是 FAST token 的自回归 likelihood。
  • 论文给出的形式是：L_inspiration = lambda_VQA * L_VQA + lambda_D * L_discrete_action。
论文没有公开 lambda_VQA 和 lambda_D 的具体数值，也没有公开不同数据源在这一阶段的精确采样比例。

这一阶段训练完成后，作者明确说模型的输出已经可以包含 chain-of-thought reasoning、sub-task prediction、FAST action tokens。

Stage 2

3. Integration Stage：从离散动作切换到连续控制

第二阶段开始真正把模型推到机器人控制空间。论文把它显式拆成两个 phase，这是整篇工作最重要的训练组织细节之一。

3.1 Phase 1：冻结 VLM，只训练连续动作分支

  • 作者先 freeze the VLM。
  • 只训练 Action FFN 下的 flow head，先把连续动作建模稳定下来。
  • 论文解释，这样可以利用 Inspiration 阶段已经学好的语义和具身理解，把它们当成可靠初始化，而不是直接让动作目标把整个 VLM 拉偏。

3.2 Phase 2：解冻后联合优化

  • 当 flow head 稳定以后，再 unfreeze the VLM for joint optimization。
  • 此时视觉、语言和动作表征会通过 attention 交互，静态路由继续把 action-centric 信息和 vision-language 信息分别送到不同 FFN。
  • 论文明确写了：第二阶段联合训练时，∂L/∂θ ≠ 0 且 ∂L/∂φ ≠ 0，也就是 VLM 和动作分支一起被更新。

3.3 连续动作目标：flow matching

  • 论文写的是 flow matching，不是普通 BC 直接回归。
  • 训练时会构造 noisy sample x_t，其中 x_0 是干净动作、ϵ 是高斯噪声、ρ(t) 是 noise schedule。
  • 模型学习的是 velocity field v_phi，损失里还包含时间相关权重 w(t) 和一个连续动作损失权重 lambda_C。
这一步的意义可以概括成：Stage 1 用离散 token 建立语义绑定，Stage 2 用 flow matching 恢复高频连续控制能力。也就是论文反复强调的 “discrete priors → continuous control”。
Uni-CoT

4. Unified Cross-Level CoT：把推理、子任务和动作串成一条链

论文的第三个关键点不是再加一个新 backbone，而是在训练目标里把 instruction → CoT → sub-task → continuous action 做成统一路径。

  • 作者明确反对“一个 VLM 做 planner，再接一个独立 controller”的 pipeline 设计。
  • WALL-OSS 采用单模型 Uni-CoT，让模型同时学会是否使用中间推理、何时生成子任务、以及如何接连续动作。
  • 论文公式里引入了 path-drop objective，允许模型在训练时“条件化使用”或“绕过”中间推理链。
论文清楚给出了 path-drop 的思想，但 没有公开 path-drop 的具体概率、链长策略或不同路径的采样权重。
Data

5. 训练数据怎么组织

数据是这篇工作的真正底座。论文明确说 corpus 由三个互补部分组成： 自采机器人动作数据、开源动作数据、多模态 VQA 数据。

5.1 总规模

  • 在数据总览段，论文写的是 “exceeds 10,000 hours”。
  • 但在数据细节段，论文又写成 “exceeds tens of thousands of hours”。
  • 比较稳妥的解读是：作者只给了下界，没有给精确总小时数；公开文本本身存在“1 万小时以上”和“数万小时级”两种表述。

5.2 机器人动作数据

  • 作者强调这部分承担高质量动作监督、复杂任务覆盖和 cross-morphology 泛化。
  • 论文举出的代表来源包括：AgibotWorld、DROID、BC-Z、RH20T、FurnitureBench、BridgeData V2、DobbE、UMI-biarm、Utaustin_mutex、Stanford_hydra、Austin_sailor、Taco_play、Berkeley_autolab_ur5、Berkeley_fanuc_manipulation 等。
  • 作者还提到会把 open-source action data 统一化，用于跨 embodiment、跨环境联合训练。

5.3 General VQA：维持和增强 VLM 能力

  • 论文明确说这条流主要是为了 VLM maintenance，即保住语言视觉能力、避免动作训练把 backbone 拉坏。
  • 代表数据源包括：CapsFusion、Cambrian、PixMo、RoboPoint、Robo2VLM、COCO、VQAv2、VQASynth-SpaceLLaVA、SpaceThinker、OpenSpaces 等。
  • 这些信号与 manipulation 相关性较弱，主要起 regularization 作用，更多约束 vision-language backbone，而不是直接训练 action head。

5.4 Embodied VQA：专门为具身空间推理服务

  • 作者在自采轨迹上建立自动生成管线，构造专门面向机器人场景的监督。
  • 具体包括：Action Planning VQA、Spatial & Temporal QA、Perception VQA、Cognition & Affordance。
  • 标签统一成结构化格式，例如 <box>[x1,y1,x2,y2]</box>、<point>[x,y]</point>，以及可选的 <mask>。
  • 论文明确说，这条 supervision 流就是在显式连接“instruction → CoT → sub-task → continuous action”这条链。
Preprocess

6. 数据标准化、采样与增强

6.1 统一标准化协议

  • 坐标与单位统一：位置统一到米，角度统一到弧度。
  • morphology normalization：用最大表达能力的 DoF 模板统一单臂、双臂、轮式、人形等平台，并对缺失关节做 mask / placeholder。
  • perception alignment：统一内外参、时间戳、帧率、分辨率和多视角通道。
  • action time-base normalization：统一控制频率，并把轨迹重采样到 flow-matching 网格。

6.2 数据混合与采样策略

  • 作者按 scene / object / task / morphology 做验证集和测试集分层切分。
  • long-horizon 和 rare skills 会得到 temperature-controlled resampling 与 hard-example upsampling。
  • 两个训练阶段都会做 source mixing with quota control，目的是同时保住 VLM 能力并提升连续控制。

6.3 数据增强

  • 论文明确提到使用 light domain randomization。
  • 视觉流上还会加入 occlusion perturbations，用于提升鲁棒性。
Long Horizon

7. 长时程任务的额外训练信号

长时程任务是论文重点强调的能力来源之一。实验部分明确写到，在 long-horizon fine-tuning 里，WALL-OSS 会 jointly train on action generation and subtask prediction。

  • 训练时同时监督动作生成和子任务预测。
  • 作者特别指出：只有 1% 的训练数据带 subtasks 标签，模型依然能学出高质量 subtask 指令。
  • 推理时，模型会先生成 subtask instruction，再用它引导动作生成。
  • 论文认为，这一步直接提升了阶段感知与任务进展建模能力，尤其对长时程任务有帮助。

  • MoE 相关配置是：num_experts = 2、mlp_moe = true、attention_moe = false。
  • 噪声调度配置写的是：beta_alpha = 1.5、beta_beta = 1.0、s = 0.999。
  • 推理时间步默认是 num_inference_timesteps = 5。这是推理配置，不是训练步数。
How To Read It

9. 如果你要复现，这篇工作的训练重点是什么

  • 先学 embodied VQA，再学动作。 论文认为动作泛化差，根源之一是 VLM 本身在 embodied scene 上就不够懂。
  • 先离散、后连续。 先用 FAST 离散动作把 VLM 拉近动作空间，再用 flow matching 拉回连续控制。
  • Stage 2 不能只训动作数据。 论文反复强调 co-training grounding / VQA 数据是为了抑制遗忘并维持 instruction grounding。
  • 长时程任务要把 subtask supervision 一起训进去。 这不是推理时临时加 prompt，而是训练目标的一部分。
  • 数据标准化是关键工程。 坐标、DoF、时间基、相机、分辨率和多源 quota control 都是训练能否稳定的前提。
Missing Pieces

10. 论文没有完全公开的训练细节

  • 没有一张完整超参数总表，系统列出 batch size、GPU 数、训练步数、optimizer、weight decay、总算力。
  • 没有公开 各数据源的精确混合比例、quota 数值或 temperature 采样参数。
  • 没有公开 Inspiration / Integration / Uni-CoT 各阶段的准确切换条件和 wall-clock 训练预算。
  • 没有公开 lambda_VQA、lambda_D、lambda_C 的具体数值。
  • 没有公开 path-drop 的概率和策略。
  • 数据规模的公开表述本身有轻微不一致：正文一处写“超过 10,000 小时”，另一处写“数万小时级”。
所以如果你的目标是“理解训练思想”，这篇论文已经够清楚；但如果目标是“逐项严谨复现”，你必须结合官方仓库、后续模型卡和自己的工程假设补全配方。
