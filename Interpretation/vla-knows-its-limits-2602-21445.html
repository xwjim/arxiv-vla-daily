VLA Knows Its Limits

论文解读：AutoHorizon 用 VLA 内部注意力判断“这段动作最多可信到哪一步”，在测试时动态决定 action chunk 的执行长度。

arXiv:2602.21445 Robotics / VLA / Action Chunking 作者：Haoxuan Wang 等 机构：UIC 与 Cisco Research 提交：2026-02-24

一句话结论

这篇论文的关键价值是把 VLA action chunking 中一个长期靠经验调参的控制量，执行 horizon，转化为一个可在线估计的模型内部信号问题：当动作 token 对边界 action sink 的自注意力开始衰减或平台化时，就说明模型对后续动作的预测可信度正在下降，应当提前重规划。
问题 固定执行长度并不稳

同一个 VLA、同一个任务，执行 horizon 从短到长会出现明显的先升后降曲线。太短会频繁重规划造成抖动，太长会让过时感知支撑后续动作。

洞察 VLA 的注意力暴露了预测边界

动作序列内部会强烈依赖首尾 action token，作者称之为 radial action sinks；这种结构可以作为模型“还能可靠往前推几步”的代理信号。

方法 AutoHorizon 是测试时方法

不重新训练模型，只读取注意力图，筛出低熵行，再用双向 soft-pointer 找到注意力推进停止的位置，动态决定本 chunk 执行多少步。

论文要解决什么问题

在 flow-based Vision-Language-Action 模型里，策略通常不是每次只预测一个动作，而是一次预测一个动作块 action chunk。模型预测长度叫 prediction horizon，真正执行前缀长度叫 execution horizon。执行完这个前缀后，机器人重新观测环境，再预测下一段动作。

这个设计天然有一个张力：

  • 执行得短：重规划频繁，反应快，但 chunk 间切换多，动作容易不稳定、犹豫。
  • 执行得长：动作平滑、连贯，但后半段动作越来越依赖旧观测，一旦环境或物体状态变化，后续动作可能失效。

以往很多工作用固定值或离线穷举选 horizon。这篇论文认为固定值本身就不合理，因为 reaching、grasping、transport、placing 等阶段对“连贯性”和“反应性”的需求不同。

核心机制图解

两个关键发现

1. 同一 chunk 内的动作反复看同一批视觉语言 token

作者观察 cross-attention 后发现，chunk 内不同时刻的动作 token 对视觉和语言 token 的关注高度相似。换句话说，模型虽然输出了一段未来动作，但这段未来动作大多建立在同一个静态感知上下文上。

这解释了为什么长 horizon 会出问题：越靠后的动作越可能被旧观测误导，尤其是物体已经移动、夹爪接触状态发生变化、目标位置需要细修时。

我的解读： 这不是简单的“模型不够强”，而是 action chunking 的结构性问题。chunk 的后半段如果没有新的观测输入，本质上是在开环控制里继续走。

2. 首尾动作 token 形成 radial action sinks

在 action self-attention 里，初始和终止动作 token 获得异常高的注意力。作者把这些边界 token 称为 radial action sinks：它们像潜在中心，组织中间动作形成平滑轨迹。

当中间动作仍强烈依赖这些边界 sink 时，说明动作序列仍被稳定锚点支撑；当注意力权重下降并进入平台期，说明后续动作越来越自引用，预测误差更容易累积。

方法直觉： 找到“注意力推进停止”的位置，就近似找到了这个 chunk 的可靠执行边界。

AutoHorizon 怎么做

AutoHorizon 的流程很轻量，核心不在额外模型，而在读出 VLA 已经算出来的注意力：

  • 从每个采样步中提取 action self-attention。
  • 跨 Transformer block 和 attention head 做平均，并对每一行归一化。
  • 计算每一行注意力分布的熵，只保留低熵行，因为低熵代表注意力更尖锐，结构信号更可靠。
  • 从 chunk 两端启动双向 soft-pointer，估计注意力质量向前或向后覆盖的位置。
  • 检测 attention trajectory 的增量变化是否低于阈值，从而找出 plateau 或 turning point。
  • 如果前向和后向覆盖足够覆盖整个 chunk，就执行完整预测长度；否则执行前向可靠前缀。
符号 含义 解读
p prediction horizon 模型一次预测多少个低层动作。
e / N execution horizon 本次真正执行多少个动作。AutoHorizon 要动态估计它。
q entropy quantile 筛选低熵注意力行的分位数，论文默认常用 0.9。
tau plateau threshold 判断注意力推进是否停滞的阈值，论文默认常用 0.3。

实验结果怎么读

92.1% π0.5 在 LIBERO-10、p=50 上 AutoHorizon 的成功率，高于 Static Oracle+ 的 91.9%。
96.7% GR00T N1.5 在 LIBERO-Spatial 上 AutoHorizon 的成功率，高于最优固定 horizon。
100% RoboTwin Adjust Bottle 上 AutoHorizon 达到 100.0 ± 0.0。
99.0% 真实机器人 Cube Bowl 任务中 AutoHorizon 的 solve rate。

LIBERO

在 π0.5 上，p=10 时固定 horizon 的最优点常常在边界 e=p，说明短预测长度下模型较擅长短段轨迹。p=50 时趋势更典型：执行太长会显著掉点，例如 LIBERO-Spatial 从 e=0.2p 的 94.9% 掉到 e=1.0p 的 71.5%。AutoHorizon 在 p=50 的四个 LIBERO 子集上分别达到 96.5%、98.0%、94.4%、92.1%，超过 Static Oracle+。

GR00T N1.5

作者也在架构和训练流程不同的 GR00T N1.5 上验证，AutoHorizon 在四个 LIBERO 子集均优于最优固定 horizon：96.7%、98.7%、96.0%、92.7%。这支持了“radial action sink 不是 π0.5 特例”的论点。

RoboTwin 与真实机器人

RoboTwin 七个任务中，AutoHorizon 通常持平或超过最优固定 horizon，尤其在 Adjust Bottle、Stack Bowls、Place Cup、Open Laptop、Press Stapler 上更高。真实 Franka 机器人上，三类 pick-and-place 任务中 AutoHorizon 分别为 98.0%、92.0%、99.0%，明显优于 Random，也优于或超过 Static Oracle+。

局限与风险

注意力是否等于可信度，仍然是经验假设。 论文用实验支持了 action self-attention 可作为 predictive limit 的代理，但这不等于注意力权重天然具备校准意义。换到其他 VLA、其他 action tokenizer 或非 Transformer 控制头时，需要重新验证。
  • 依赖可访问注意力： 如果模型推理框架不暴露 action self-attention，AutoHorizon 的接入成本会变高。
  • 任务失败模式可能不只由 horizon 决定： 物体遮挡、抓取失败、视觉误检、语言歧义等问题，不一定能靠缩短 horizon 解决。
  • 真实实验规模有限： 真实机器人每个设置十次 trial，能说明趋势，但还不足以覆盖工业级鲁棒性。
  • 阈值仍存在默认选择： q 和 tau 虽然在消融中较稳定，但如果模型注意力分布形态差异很大，仍可能需要校准。

对后续研究的启发

  • 把 VLA 的内部信号用于控制层调度： 不只 horizon，重规划频率、控制速度、置信触发器都可以从内部表征中读出。
  • 训练时加入 horizon-aware objective： 既然 attention sink 能反映预测边界，可以考虑训练模型直接输出 calibrated predictive horizon。
  • 与不确定性估计结合： AutoHorizon 是结构信号，若结合多样本 action variance 或视觉置信度，可能更稳。
  • 用于异步推理： 在大模型推理慢于控制频率时，动态 horizon 可以决定何时复用旧 chunk，何时必须等新预测。
  • 诊断 VLA failure： cross-attention 不变性和语言 token 冗余现象提示，很多 VLA 的语言 grounding 可能已经被视觉 token 吸收，显式语言注意力未必是动作语义来源。
